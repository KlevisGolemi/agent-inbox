# Cowork Queue v2 — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** fusionner `webhook-queue` et `cowork-mcp` en une app TypeScript unique, MCP stateless, OAuth 2.1 + clés API, réglages à chaud en base, installable par n'importe qui.

**Architecture :** une app Express 5 qui monte quatre surfaces (`/webhook…` API file, `/mcp`, `/oauth` + `/.well-known`, `/admin`) sur une base SQLite unique. Chaque module expose une factory qui reçoit ses dépendances (`db`, `settings`) : pas d'état global, tests sans réseau via `createApp()`.

**Tech Stack :** Node 24 LTS · TypeScript strict (ESM, NodeNext) · Express 5 · better-sqlite3 · `@modelcontextprotocol/sdk` 1.x (≥ 1.31) · zod 4 · express-rate-limit 8 · Vitest + Supertest · ESLint 9 (flat) + Prettier.

**Spec :** [`docs/superpowers/specs/2026-10-01-v2-refonte-design.md`](../specs/2026-10-01-v2-refonte-design.md)

## Global Constraints

- Node `>=24`, `"type": "module"`, TypeScript `strict: true`, `noUncheckedIndexedAccess: true`.
- Aucune dépendance runtime hors : `express`, `better-sqlite3`, `@modelcontextprotocol/sdk`, `zod`, `express-rate-limit`, `cookie-parser`.
- Hachage mot de passe : `node:crypto` `scrypt` (N=16384, r=8, p=1, keylen 64, sel 16 octets). Jetons/codes/clés/sessions : SHA-256 hex en base.
- Regex correlation_id : `^[A-Za-z0-9_-]{1,128}$` (une seule constante exportée par `src/queue/validation.ts`).
- API file compatible v1 à l'octet près sur les chemins, headers (`x-webhook-secret`, `x-source`, `x-correlation-id`) et codes (200/400/401/404/409/410/413/429).
- Env de démarrage uniquement : `PUBLIC_URL` (obligatoire, https sauf `NODE_ENV=development`), `PORT` (3000), `DB_PATH` (`/data/queue.db`), `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `NODE_ENV`. Graines v1 lues une seule fois : `WEBHOOK_SECRET`, `TTL_HOURS`, `CLEANUP_INTERVAL_MIN`.
- Réglages et bornes : `ttl_hours` 1–8760 (48) · `cleanup_interval_min` 1–1440 (60) · `webhook_rate_limit_per_min` 1–10000 (100) · `webhook_secret` 32–256 car. · `update_check_enabled` bool (true).
- Access token 1 h · refresh token 30 j avec rotation · code d'autorisation 10 min · session admin 7 j · PKCE S256 obligatoire.
- Clés API : `cwk_` + 32 car. base62, préfixe affiché = 8 premiers car.
- Logs JSON une ligne (`ts`, `level`, `msg`, champs) ; jamais de secret, jeton, mot de passe ou payload complet dans les logs.
- Messages d'UI et docs en français ; identifiants de code en anglais ; Conventional Commits.
- Licence MIT.

## Review Focus

1. **Base v1 réelle avec données** → migrée sans perte ; la graine `WEBHOOK_SECRET` de l'env n'écrase jamais une valeur déjà en base (rotation UI préservée après redémarrage). Test : Task 2 + Task 3.
2. **Deux consommateurs simultanés sur `/next`** (deux connexions SQLite sur le même fichier) → deux messages distincts, jamais le même. Test : Task 4.
3. **`redirect_uri` non enregistrée ou PKCE absent** sur `/authorize` → refus, aucune redirection vers une URL arbitraire. Test : Task 8.
4. **Réglage invalide** (`ttl_hours: 0`, `-1`, `"abc"`) via l'admin API → `400`, valeur précédente conservée. Test : Task 3 + Task 10.
5. **Jeton expiré/révoqué ou refresh token réutilisé après rotation** → `401` avec `WWW-Authenticate: Bearer resource_metadata=…` ; refresh réutilisé → `invalid_grant`. Test : Task 8.
